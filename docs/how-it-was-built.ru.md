# Как это сделано

VoxCut сделан за две недели (14–27 октября 2026) человеком и ИИ-агентом для программирования. Здесь описаны метод, шесть эпизодов, где что-то пошло не так и как это поймали, и что до сих пор не сделано.

## Метод

**Роли.** Человек задавал требования и принимал все проектные решения. Агент писал код, тесты и документы и предлагал варианты с их ценой. Когда задаче нужно было решение, которого нет в журнале, агент останавливался и спрашивал.

**Цикл.** Решение → план → тест → код → мутация → ревью.
- Новая функция начинается с обсуждения дизайна. Его итог — пронумерованные решения в [журнале решений](decisions.md).
- План делит работу на слои (чистая логика, затем аудио, затем CLI, затем интерфейс), у каждой задачи есть критерий готовности.
- На каждую задачу: сначала тест критерия, потом код; линтер и быстрые тесты зелёные; затем одна-две намеренные мутации кода, каждая из которых должна покрасить тест; затем коммит.
- На границе слоя свежий ревьюер читает дифф слоя и пытается нарушить жёсткие правила, которых он касается. В конце плана — ревью всего диффа и полный набор тестов.

**Жёсткие правила.** Несколько правил не обсуждаются, потому что их нарушение теряет речь или данные: исходная запись никогда не меняется; артефакты — неизменяемые каталоги прогонов; ffmpeg только через один помощник и никогда через shell; цикл модели только под `inference_mode` в одном потоке; тяжёлая работа только с лимитом памяти.

**Измеренная приёмка.** «Не потерять голос» превратили в числа до всякой настройки: полнота по времени, полнота по фразам, фразы, пропущенные целиком, и бюджет минут клипов на час. Протокол разметки, включая случайный аудит звука вне кандидатов, зафиксирован до прослушивания.

**Цифры.** более 360 коммитов в этом репозитории; 136 решений и 7 исправлений; 23 плана и 7 спецификаций дизайна (хранятся вне этого репозитория); около 4 100 строк Python и 2 300 строк JavaScript; около 1 000 тестов (около 950 случаев Python, 62 JavaScript).

## Эпизоды

**1. Утечка памяти, найденная до кода.** Перед тем как писать цикл модели, короткие пробы проверили окружение. Одна показала рост памяти примерно на 21 КБ на кадр звука без `torch.inference_mode()`: около 7 ГБ на трёхчасовую запись. Это стало жёстким правилом и тестом на 50 000 кадров ([C1](decisions.md); [27168c7](../../../commit/27168c7f1bbfa7e1dce1956f606081112dea64d7)).

**2. Тест памяти мерил не то.** Мутация, экспортирующая весь интервал сразу, а не блоками, прошла тест памяти. Тест читал `ru_maxrss` — пик всего процесса, который уже подняли более ранний тест или родительский pytest с загруженным torch. Исправление меряет пик памяти в свежем процессе через `VmHWM` ([766df3a](../../../commit/766df3a88baa26f10164fde0d08d7e8dffd9f988)).

**3. Шёпот под музыкой не слышен.** В окнах аудита пилота был шёпот, получавший 0.000–0.009 при сквозном прогоне: на долгой музыке рекуррентное состояние модели «глохнет». После свежего сброса тот же шёпот получал 0.05–0.26. Теперь VoxCut делает второй проход со сбросом каждые 120 с и берёт максимум. Целиком пропущенных событий стало 0 из 128 вместо 5 ([D31](decisions.md); [a56ee75](../../../commit/a56ee75239c984ec40922aaebde21b5c39861b35)).

**4. Отложенный час сказал «нет».** Стартовый конфиг выбрали на части development, и он не прошёл на отложенном часе: полнота по времени 0.945 при пороге 0.975. Каждый непокрытый кусок был краем шёпота рядом с клипом. Запас 3 секунды это исправил, а журнал прямо говорит: запас выбран с оглядкой на отложенный час, так что этот час израсходован ([D36, D37](decisions.md); [b15a012](../../../commit/b15a0122baad01e418ddd83dbfdd2725f6e4b90e)).

**5. Тяжёлый прогон уронил всю систему.** Под WSL тяжёлый прогон исчерпал память, и завершение по нехватке памяти забрало с собой init WSL: погибло всё Linux-окружение. С тех пор каждый тяжёлый шаг идёт как пользовательский юнит systemd с `MemoryMax=5G` и без swap; задачи интерфейса — такие же юниты ([9abcf30](../../../commit/9abcf3088ccd8d11cd3d3d3b1702726789d4214d)).

**6. Ревью нашло чтение без предела.** Локальный сервер интерфейса принимал `Content-Length: -1`, и чтение тела запроса читало сокет без предела. Это поймало ревью; теперь заголовок должен быть обычным десятичным числом в пределах лимита ([3fcba6a](../../../commit/3fcba6aefe1f78061381e19515fdb9dfa28f7cdc)).

## Что не получилось

- **Отложенный час израсходован.** Единственная размеченная сессия использована и для выбора, и для проверки. Для следующей честной проверки нужна новая размеченная сессия.
- **Нет распознавания речи.** VoxCut заканчивается клипами с манифестом; распознавание — следующий этап.
- **Одна платформа для интерфейса.** Только Windows 11 с WSL2 и Microsoft Edge.
- **Точность остаётся низкой.** Детекторы, которые могли бы отличить пение от речи, сделали только хуже ([D33](decisions.md)), так что большинство клипов по-прежнему разбирает человек.

Документы процесса (спецификации, планы, заметки ревью) убраны из истории при публикации репозитория. Сообщения коммитов по-прежнему их упоминают.
