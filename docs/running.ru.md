# Установка и запуск VoxCut

У VoxCut есть командная строка для Linux и интерфейс для Windows. Обработка локальная. Интерфейс работает в WSL2 и открывает Microsoft Edge; устанавливать Python в Windows не нужно.

- [Ubuntu: командная строка](#ubuntu-командная-строка)
- [WSL: подготовка один раз](#wsl-подготовка-один-раз)
- [Windows: клон и двойной клик](#windows-клон-и-двойной-клик)

## Пререквизиты

- **CLI в Ubuntu:** Ubuntu 24.04 или другой Linux с Python 3.12+, `make`, ffmpeg и libsndfile.
- **Интерфейс в Windows:** Windows 11, WSL2 с Ubuntu 24.04 и включённым systemd, Microsoft Edge.
- Доступная для записи папка продукта на локальном Windows-диске или внутри WSL. Код, `.venv`, `inbox/`, `data/`, `backups/` и сведения о заданиях остаются в ней. Сетевые папки и папки облачной синхронизации не поддерживаются.
- Интернет для первоначальной установки зависимостей. Если используете прокси, оставьте его включённым. Обычная работа использует установленную модель без скачиваний.

## Ubuntu: командная строка

Один раз установите системные пакеты в терминале Ubuntu:

```sh
sudo apt update
sudo apt install python3 python3.12-venv make git ffmpeg libsndfile1
```

Клонируйте или распакуйте VoxCut в доступную для записи папку, откройте в ней терминал и выполните:

```sh
make setup
.venv/bin/python -m voxcut.cli --help
```

`make setup` устанавливает закреплённую CPU-сборку torch. Оконный интерфейс требует Windows и WSL; в обычной Ubuntu доступен CLI.

## WSL: подготовка один раз

Если WSL отсутствует, выполните в PowerShell от администратора и завершите первоначальную настройку Ubuntu:

```powershell
wsl --install -d Ubuntu-24.04
```

Проверьте установку в PowerShell:

```powershell
wsl -l -v
```

Ubuntu должна использовать версию **2**. Для продукта на Windows-диске VoxCut использует дистрибутив по умолчанию, отмеченный `*`. При необходимости выберите Ubuntu:

```powershell
wsl --set-default Ubuntu-24.04
```

В Ubuntu установите системные пакеты из раздела выше. Проверьте systemd:

```sh
systemctl --user is-system-running
```

`running` или `degraded` означает, что менеджер доступен. Если подключиться не удаётся, убедитесь, что `/etc/wsl.conf` содержит следующие строки, сохранив остальные настройки:

```ini
[boot]
systemd=true
```

Завершите текущую работу в WSL и выполните `wsl --shutdown` в PowerShell: команда останавливает **все** дистрибутивы WSL. Затем снова откройте Ubuntu.

Для продукта, расположенного внутри WSL, выполните из его папки:

```sh
python3 -m voxcut.bootstrap
```

Команда подготовит отсутствующее окружение и откроет интерфейс. После `make setup` также работает `make ui`. Двойной клик по `VoxCut.cmd` через `\\wsl.localhost\<Distribution>\...` автоматически выбирает дистрибутив из пути.

## Windows: клон и двойной клик

1. Клонируйте или распакуйте VoxCut в доступную для записи локальную папку, например `C:\Apps\VoxCut` или `D:\Audio tools\VoxCut`. Поддерживаются пробелы, кириллица и квадратные скобки в пути.
2. Дважды нажмите **VoxCut.cmd**. Первый запуск подготовит `.venv` внутри этой папки; дождитесь окончания установки. Если отсутствуют системные пакеты, появится инструкция; автоматической установки с правами администратора нет.
3. Оставьте терминал открытым, пока пользуетесь окном Edge. Ctrl+C останавливает интерфейс; уже запущенные задания продолжаются через systemd. Повторный запуск открывает ещё одно окно того же продукта.
4. Положите WAV-файлы в `inbox/<папка сессии>/`, затем нажмите «Импорт» и «Обработать» в Библиотеке.

Редактировать скрипты под имя папки или пользователя Windows не нужно. У разных папок продукта отдельные данные и серверы. Только временные файлы связи между запусками находятся в приватном runtime-каталоге WSL; записей, заметок и результатов обработки там нет.

Перед обновлением или переносом остановите интерфейс и дождитесь завершения заданий. Перемещайте **всю** папку, включая скрытое содержимое, затем снова запускайте двойным кликом. Launcher обновляет окружение, если его записанное расположение изменилось. При переносе на другой компьютер нужно подготовить WSL и системные пакеты на новой машине.

## Прокси: оставьте включённым

VoxCut не отключает v2rayN, системный прокси или TUN. Установка зависимостей наследует proxy-переменные WSL и не повторяет попытку с их очисткой. Тяжёлые задания обработки остаются офлайн, с сетевой изоляцией.

При использовании системного Windows-прокси убедитесь, что существующий `%USERPROFILE%\.wslconfig` содержит эти настройки, сохранив другие записи:

```ini
[wsl2]
networkingMode=mirrored
autoProxy=true
```

Примените изменения через `wsl --shutdown`, предварительно завершив другую работу в WSL. У Microsoft описаны [mirrored networking и наследование прокси](https://learn.microsoft.com/en-us/windows/wsl/networking). Если WSL не наследует прокси, задайте `HTTP_PROXY` и `HTTPS_PROXY` в Ubuntu с HTTP-адресом из настроек вашего прокси-приложения. Не угадывайте порт и не публикуйте адреса с учётными данными. TUN может маршрутизировать трафик без этих переменных.

Интерфейс подключается к **127.0.0.1**, на той же машине. Если сервер стартовал, но Edge не открывает страницу, проверьте, разрешён ли локальный loopback-трафик в правилах прокси/TUN. Открывать сервер для локальной сети или добавлять исключение firewall не требуется.

## Если не запускается

Оставьте прокси включённым. В PowerShell перейдите в папку продукта и сохраните окно с ошибкой:

```powershell
Set-Location -LiteralPath 'C:\Apps\VoxCut'
cmd /k .\VoxCut.cmd
```

- **Нет дистрибутива / выбран неподходящий:** проверьте `wsl -l -v` и выберите подготовленную Ubuntu по умолчанию.
- **Нет пререквизитов / старый Python:** установите перечисленные пакеты Ubuntu; используйте Ubuntu 24.04 с Python 3.12+.
- **Недоступен systemd:** выполните раздел подготовки WSL.
- **Не установились зависимости:** проверьте доступ через прокси из WSL и повторите запуск; не отключайте прокси и не удаляйте `data/`.
- **Небезопасный runtime-каталог:** не ослабляйте права; остановите другой экземпляр и проверьте владельца и ссылки у указанного каталога.

Для проверки окружения при работающем интерфейсе выполните `make ui-envcheck` из папки продукта в Ubuntu/WSL. Перед обновлением со старой версии закройте её UI: расположение временных файлов связи изменилось.
