# VoxCut

Находит речь одного человека, включая шёпот, в многочасовых записях с микрофона под музыку и нарезает её на клипы для последующего распознавания.

**Коротко**
- Положите часовые WAV-файлы диктофона в папку. VoxCut соберёт сессию, прогонит по ней Silero VAD и нарежет клипы с запасом и манифестом.
- Разбор клипов с клавиатуры: оставить или отбросить как вокал, музыку, шум или другое. Ничего не удаляется.
- Полнота важнее точности. На калибровочной сессии не потеряна ни одна размеченная фраза; цена — около 16 минут клипов на прослушивание на час записи.
- Только локально: CLI на Python и интерфейс в браузере на 127.0.0.1. Ничего не уходит с машины.

![VoxCut: импорт, обработка, разбор клавишами, заметка, «Мои клипы»](docs/demo.gif)

## Почему это трудно

Две цели тянут в разные стороны. Детектор не должен потерять ни одной фразы, включая шёпот и бормотание, и не должен утонуть в вокале, музыке и шуме.

- **Шёпот под музыкой.** На долгой музыке рекуррентное состояние модели «глохнет»: при сквозном прогоне шёпот получал 0.000–0.009. VoxCut делает второй проход со сбросом модели каждые 120 с и берёт максимум из двух ([D31](docs/decisions.md)).
- **Пение похоже на речь.** Отделение вокала (Demucs) и другой VAD сделали только хуже: в пять раз больше ложных срабатываний ради небольшой прибавки полноты ([D33](docs/decisions.md)).

Поэтому разделение намеренное: детектор ничего не выбрасывает, лишнее отсеивает быстрый разбор клавишами.

## Статус

Полной автоматизации нет. Полнота измерена и высокая; точность низкая намеренно. Большинство клипов требует решения человека, и экран разбора сделан так, чтобы это было быстро.

## Первая калибровка

Одна многочасовая запись размечена вручную: все кандидаты целиком плюс случайный аудит 20 % звука вне кандидатов. Один час отложен для проверки.

- Стартовый конфиг прошёл на development и **не прошёл на отложенном часе**: края шёпота длиной до 4 с оказались сразу за границами клипов ([D36](docs/decisions.md)).
- Запас 3 с с каждой стороны клипа это исправил: development — полнота 0.999 по времени и 1.000 по фразам, ни одна фраза не потеряна; отложенный час — 0.981 и 1.000, ни одна не потеряна. Цена — 15.7 минуты клипов на час записи ([D37](docs/decisions.md)).
- Запас выбирался с оглядкой на отложенный час, так что этот час израсходован. Следующая честная проверка — новая размеченная сессия.

**Дальше:** докалибровка на новых размеченных записях и отброшенные клипы как негативы для настройки детектора.

## Быстрый старт

```sh
sudo apt install ffmpeg libsndfile1 python3.12-venv
make setup    # .venv с CPU-сборкой torch
make ui       # открывает интерфейс в окне Edge
```

Положите WAV-файлы сессии в `inbox/<любая папка>/`, затем «Импорт» и «Обработать» в Библиотеке.

**Требования.** Интерфейс: Windows 11 с WSL2 (systemd включён) и Microsoft Edge. CLI (`.venv/bin/voxcut --help`): любой Linux с Python 3.12 и ffmpeg.

## Как это работает

1. **Сессия.** Часовые файлы проверяются (структура RIFF, согласие декодеров, кодек) и бит в бит собираются в один WAV; стыки записываются.
2. **Вероятности.** Silero VAD в два прохода, со сбросами на стыках и каждые 120 с; сохраняется максимум.
3. **Отрезки.** Порт гистерезиса Silero, затем запас и склейка близкой речи.
4. **Клипы.** Нарезаются из источника бит в бит, с манифестом времён, сессии и стыков для распознавания.
5. **Разбор.** Решения и заметки пишутся в журнал, который только дополняется. Каждый каталог прогона неизменяем.

Тяжёлые шаги идут как пользовательские юниты systemd с лимитом памяти, так что большая запись не уронит машину.

## Безопасность

Сервер интерфейса слушает только 127.0.0.1, проверяет Host и Origin и требует ключ окна, полученный обменом одноразового кода запуска; строгая Content-Security-Policy запрещает встроенный код. Известное ограничение: код запуска виден другим локальным процессам в командной строке Edge до 30 секунд, пока не использован.
